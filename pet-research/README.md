# PET科研多智能体协同 Demo

打开 `../awiki-pet-research-demo.html` 即可本地离线运行。页面内联全部JS/CSS，无模型、数据库、仪器或网络依赖。设计文档：`../awiki-pet-research-design.html`。

- 构建：`node pet-research/build.mjs`
- 验证：`node --test pet-research/*.test.mjs coffee-demo/*.test.mjs`
- 不修改原咖啡Demo及coffee-demo依赖。
- 浏览器状态在localStorage；建议先导出再重置。文件协议的存储行为依浏览器而异；存储失败会显示提示。
- 导出共享事件、回单、结果与阶段契约，不导出私人备注。导入外部JSON未实现；刷新和“重放校验”使用本地命令日志。

## 人工流程

1. 初始不推进。可在SIDE能力活动中选择共享事件，以当前主体有效绑定角色形成Task，再任意选择I/S/D/E；能力可往返，D只形成澄清提议，再返回客户确认。
2. 客户代表选择S1或S2（仅Demo确认）；选择澄清保留争议。
3. 单步/自动播放到L3停止。选择项目负责人，批准v1。
4. 继续到L5停止。选择实验专家，审阅方案、TC-01及来源窗口，批准。
5. 继续到L6。实验员依次接受卡、提交操作回执、载入并确认演示测量。
6. L7显示模拟质检、严格阈值评价、候选知识与下一轮建议。负责人批准下一轮。

## 设备、异常、版本演示

- 在“执行与授权”以专家角色切换设备模式、配置250–285℃和有效校准；变更生成新版本并回到L5重新批准。
- L6切换模拟Agent角色执行；验证audience/resource/action/purpose、任务版本、参数与校准。
- 参数300℃或校准无效会暂停；专家纠错、重新批准才可恢复。
- 客户代表可在Board重新选择温度基线；旧测量保留但不适用于新版本。
- 负责人撤销授权后，所有执行仍被阻断；修订不能恢复授权。重置开始全新本地演示。
- 异常测量隔离于L6；有效测量才交接L7。
- D1仅可载入人工历史演示结果，明确非TC-01执行产物；因详细卡缺失，设备模式拒绝。
- 角色选择器只是模拟会话角色，不提供真实安全保证。

## 最终修订交互

L7批准后本轮完成，不能重复批准。负责人点击“创建下一轮提案 → 专家重审”，新版本进入L4，再到L5由专家重新批准。所有mode/config/baseline/revise/next-round版本变更均失效当前批准；历史审批记录绑定stage/version保存。

Board提供“提议变更温度条件 / 重新客户确认”入口。结果页仅评价当前版本有效测量；旧版本只读历史，异常测量只看隔离原因与证据。主时间线每级包含实质Agent来源消息与冻结输入/输出工件，支持普通群内本地备注；私人建议随阶段变化。


## SIDE新机制（来源已核验）

来源见SIDE-SOURCES.md。旧TREE顺序运行入口已撤下；旧日志只归档，不会转换为SIDE活动或批准。

- “SIDE能力活动”：先选共享事件，再在有效绑定内解释为Task，然后选择I/S/D/E，允许任意往返，不映射L等级。
- 默认客户与专家对同一温度事件形成不同任务；切换预置模拟主体不会赋予其未绑定角色。
- 访客建议使用专家/负责人角色时只形成候选Task；不能调用受控能力或批准。
- 负责人可以令实验员/专家/Agent角色到期或撤销，也可以只撤销独立授权；再切换目标主体测试L6和SIDE拒绝。
- Board链接SIDE活动，每项保留输入来源、环境版本、角色依据、任务、能力解析、权限判断和回单。
- 配置Matter在执行与授权页展示模式/参数差异、影响、专家批准及发布回单；SIDE不替代它。
- AIC检查器展示当前有效语义与来源索引；不是全部历史，不声称密码学验证。

证据归属：四附件SHA复算与初版CUA浏览器QA由本会话根线程Codex实际执行，非人类用户测试。云端负责正文交叉核对、实现及Node/VM测试；最终SIDE提交交由根线程拉取并执行真实浏览器回归，不能把初版结果冒充最终版。
