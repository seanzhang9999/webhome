# 厦门咖啡进口智能体网络 Implementation Plan

**Goal:** 新增可离线运行的三群联动咖啡进口演示，面向厦门政府部门展示企业委托、跨时区协作与可审计履约，并发布到现有 GitHub Pages。

**Architecture:** 保留原外贸演示的 AWiki 导航、事项列表、主群聊和私人伙伴三栏结构。以确定性事件序列、显式人员决策门、暂停/撤回和持久化实现故事；场景数据、状态机、渲染分离。静态打包为独立 HTML，无生产依赖和远程服务调用。

**Tech Stack:** Semantic HTML / CSS / JavaScript modules, Node built-in test runner, static single-file build.

## 范围与审计

本次明确目标是 seanzhang9999/webhome 的新展示页，不修改 demo_chain 慢病应用，不执行其历史首次启动里程碑。webhome 无 AGENTS.md。原 awiki-foreign-trade-demo.html 保持不变。

原页面：70px 导航、282px 事项列表、中央时间线、326px 私人伙伴；白灰产品壳、蓝色人员动作、紫色智能体、绿色回单、琥珀色风险；支持 modal。现有推进按钮主要来自 stepActions() 并在右栏，主聊天仅追加消息。原导航使用工作入口，下属事项/资源/专题/方案；新页遵循原版消息/一览/连接/AWiki/工作/设置；工作内分事项、资源、专题、方案，方案是已安装的可复用能力包。

## 方案取舍

1. 推荐三群联动：采购委托与撮合、正式贸易洽谈、成交后履约。每次跨群使用上游决定和冻结的业务快照，分配最小必要权限。
2. 单群到底：上下文连续但边界混乱，内部预算和供应商信息容易混入同一受众，不采用。
3. 政府指标大屏：容易理解宏观价值，却难以证明真实协作机制，仅保留结尾的试点评估说明。

## 故事与身份

厦门鹭屿咖啡贸易有限公司、负责人林岚、巴西 Serra Azul Export（均为虚构）。采购 19,200kg 阿拉比卡生豆，320袋×60kg，经桑托斯港至厦门。所有报价、航期、报告、回执均为预置虚构数据。

第一群：人描述意愿→撮合澄清→人确认委托M01→中国下班、巴西上班→撮合与值班智能体补资料→供应商要求40%预付锁货→值班智能体拒绝越权→次日伙伴晨报→人决定继续尽调/询样→专业核验与样品杯测的模拟人员回单→伙伴建议正式谈→人批准第二群。夜间可收资料，不得披露预算、承诺价格/订金、接受合同。继续、暂停/恢复、撤回/重置都有实际效果。

第二群：买卖双方人员与Agent协商数量、质量、CIF厦门报价、交期和付款→明确CIF风险转移与保险需专业确认→合同中英文差异→专业人员复核→具名负责人批准签约→外部双方签署模拟回执。批准不等于已签署。

第三群：合同快照派生最小共享任务→付款需财务授权与外部回执→订舱和装运→单证预审发现320/300袋差异→补正与关务人员复核→人员确认申报委托→模拟单一窗口受理/海关查验/准予进境结果→到仓验收→结算复核/付款回执→复盘，下一轮采购仍待重新授权。

## 面向政府的试点评估（建议，不是已实现成效）

选择自愿企业和合规服务机构小范围试点。衡量跨时区首响时长、人员处理时长、首次单证通过率、越权拦截及人工确认留痕完整率。先取得基线再评估，不宣称交易额增长或通关提速。企业保有商务决策权；政府仅在合法授权和明确口径下获得汇总信息。
