SOLUTION BRIEF · V1.0

让已有的专业 AI 应用，成为 AWiki 伙伴接单决策的一部分

在化工数字空间的需求喊单场景中，AWiki 伙伴调用 DocPilot 企业合规风控服务，先把结果以可解释的卡片预览给业务人员；需要复核证据或修改规则时，再打开 DocPilot 原应用。

不要求合作伙伴先改造成 Agent

这不是“再造一个合规 Agent”

DocPilot 保持其专业应用身份和规则、证据、人工复核能力；AWiki 伙伴只负责在正确的事项、正确的决策关口，发起受控调用并把结果组织给人。

✓
专业能力留在原应用，业务决策回到事项风险服务给出事实、规则命中、材料差异与修改建议；AWiki 伙伴结合产能、付款政策和当前协作上下文，形成“是否接单、以什么条件接单”的建议。最终承诺仍由具名人员作出。

接单前的最小闭环

调用发生在工厂机会响应 Agent 收到喊单之后、工厂人员发送业务响应之前。

01可信喊单送达需求 Agent 提交签名需求；匹配服务把范围化邀请送到工厂。
02AWiki 伙伴发起核验仅提交需求主体、必要附件、公开查询条件与当前事项用途。
03DocPilot 形成结果主体、信用、材料一致性、风险项与证据定位保留在原服务。
04AWiki 伙伴卡片预览以“可否接单、需要哪些条件”呈现给供应商经理。
05人员确认与回单有条件响应、补证或暂缓；经确认后才由机会响应 Agent 发信。

各方责任不混淆

1DocPilot 专业服务

执行企业尽调、材料一致性、规则审查、合同审核；返回结果摘要、证据索引与需要人工复核的项目。

2AWiki 伙伴

在事项授权范围内调用服务，结合当前任务生成易理解的接单建议；不把专业结论伪装为自身判断。

3业务责任人

确认接单条件、补证请求、暂停或拒绝；只有其确认的内容进入跨组织事项并触发后续 Agent 行动。

第二个调用点：正式合作前的合同审核

双源供货方案冻结后，AWiki 伙伴可将合同草案中必要的主体、资质、签字与条款字段提交给 DocPilot。风险服务检查合同主体资格、公司信息一致性、授权签字、权责和违约条款；结果在合作事项中形成“合同审核关口”，但不自动签约或触发付款。
