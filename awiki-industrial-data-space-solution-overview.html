AWIKI INDUSTRIAL DATA SPACE · SOLUTION OVERVIEW

把产业数据空间、Agent 与既有企业服务，落到每个工作人员的“接单—协作—履约”过程里

AWiki 由基础产品与可安装服务包组成。AWiki Me 提供身份、消息、一览、连接、AWiki、基础设置和通用伙伴；“产业链协同贸易”等服务包进一步提供工作对象、专业伙伴经验、Agent与应用连接、业务规则和扩展设置。

方案目标总体逻辑产品分层功能闭环设置边界业务闭环合规服务

要解决的不是“没有数据”，而是数据空间没有进入岗位的日常决策

化工供需协同中，需求、产能、质量、履约、风控和责任人分散在多个组织与系统。即使已有数据空间或 Agent，业务人员仍要自己判断：这单从哪里来、能否接、谁来确认、哪些信息能共享、出了问题谁处理。

◎
AWiki 伙伴将“可信连接”转成“可办理的工作”外部喊单不是自动成交；它先成为一件有目标、责任人、权限、证据、状态和回单的事项。Agent 可以建议、检索和执行，但不能越过人的业务承诺。

数字空间支撑数据流通，AWiki承接业务协同

数字空间是可信数据、身份、授权和回单底座。上下游企业通过各自 Agent 与数字空间连接，一方面提供经授权的数据或证明，另一方面获得基于数据的发现、撮合、预测和履约服务。

六套闭环构成完整功能体系

每套闭环都从一个真实输入开始，以人员可确认、结果可追踪、下一步可接续结束。界面入口服务于闭环，而不是彼此孤立的功能模块。

01 · IDENTITY & RELATION

身份与关系建立闭环

用户先明确当前代表个人还是组织、处于哪个工作域，再连接人员、群组、Agent、设备和服务账号。身份决定可见范围与发送主体，关系建立后仍需按用途单独授权。

身份与工作域 → 建立连接 → 核验关系 → 明确授权 → 开始沟通或协作
02 · INFORMATION TO WORK

信息到达与形成工作闭环

人员、应用和 Agent 的投递先进入消息或 Inbox；一览聚合变化，AWiki伙伴帮助筛选和解释。只有经过人员确认，信息才创建新事项或关联到已有事项。

消息 / 投递 → Inbox与动态 → 伙伴整理 → 人员确认 → 创建或关联事项
03 · DISCOVER & INSTALL

能力发现与安装闭环

用户在 AWiki 发现方案、Agent、知识与社区。加入社区只建立关系；采用能力时先形成配置事项，明确连接、权限和规则，经批准后安装到“工作”。

发现能力 → 伙伴评估 → 配置事项 → 人员批准 → 安装服务包
04 · MATTER COLLABORATION

事项协作与执行闭环

一笔业务的采购方、工厂、服务商、人员和 Agent 在事项群中共享必要事实。AWiki伙伴在右侧做私人分析，人员作出决定后再指派执行，结果以状态和回单返回事项。

外部事件 → 事项群 → 伙伴分析 → 人员决定 → 指派执行 → Receipt回单
05 · AI SERVICE INTEGRATION

专业 AI 与应用调用闭环

事项需要尽调、合同审核或质量分析时，AWiki伙伴调用已有专业应用，先在卡片中预览结论；需要核验时进入原应用查看证据，人员确认后把摘要与处理结果写回事项。

事项需求 → 调用专业应用 → 卡片预览 → 原应用复核 → 人员确认 → 结果回写
06 · DATA TO EXPERIENCE

数据服务与经验沉淀闭环

企业 Agent 将经授权的数据或证明接入数字空间；撮合服务结合已有数据产品与本次实时投影完成计算。结果进入事项，资源和专题沉淀证据与经验，成熟方法再形成可复用方案。

企业数据 → 授权投影 → 撮合服务 → 业务结果 → 资源 / 专题 → 方案复用

基础设置与服务包设置分层管理

AWiki Me 的通用能力始终存在；服务包只注入本业务所需的工作对象、规则和连接配置，不改变基础产品的对象含义。

从可信供给到履约回单的完整业务闭环

每段协作在相应事项中连续发生，并通过确认、授权和回单保持上下文与责任可追溯。

01 · REPORT工厂报送可信能力人员批准后，数据报送 Agent 从 ERP/MES/DCS 生成可承诺产能、窗口与质量等级证明。
02 · MATCH需求喊单与候选发现需求 Agent 提交签名需求；公共匹配服务只使用合规数据产品寻找候选工厂。
03 · DECIDE工厂判断是否接单AWiki 伙伴汇合产能、风险、质量和合作条件，供应商经理在事项中决定有条件响应、补证或暂缓。
04 · COOPERATE形成跨组织合作冻结双源组合、交付与质检框架；合同审核、报价隔离与责任边界进入合作事项。
05 · EXECUTE内部排产与履约回单各组织只接收本方任务投影；排产写回、物流、质检、签收和结算以 Receipt 回流长期事项。

DocPilot 在整体中的位置：专业风险能力，而不是被伪装的“合规 Agent”

DocPilot 作为可插拔专业服务接入当前工作。AWiki 伙伴使用其风险结论与证据索引，但不复制 DocPilot 的证据链、规则配置或人工审核界面。

D接单前：需求方资质与交易风险核验

收到喊单后，AWiki 伙伴在当前事项授权范围内把需求主体、必要附件、公开查询条件和用途交给 DocPilot。

AWiki 伙伴卡片预览：主体一致、未命中失信 / 被执行；2 项历史合同纠纷；缺少最新审计材料。
建议：可有条件响应，正式报价前补材料，首单分批交付并设置付款条件。

↗合作前：合同审核关口

双源供货方案冻结后，合同草案进入 DocPilot 的主体资格、公司信息、签字授权、权责和违约条款审核。

边界：服务结果可以形成风险建议与证据索引，但不能自动签约、自动付款，也不能替代法务的人工复核。

演示数据说明：组织、订单、指标与风险结论均为虚构研讨数据。DocPilot 仅作为合作伙伴能力的脱敏接入示例，不包含其后台界面、真实客户信息或真实风控结果。
