01 / 读图顺序

把五种关系分开，复杂协作就容易讲清

主体拥有能力

采购方、供应方和服务机构分别拥有自己的端、Agent、数据及业务系统。企业 Agent 代表本方在授权内做事；人的私人伙伴帮助本人判断。

方案定义方法

各端加载同一方案，理解相同的角色、事项模板、数据结构和交接规则。加载同一方案不要求共用一个 Agent，也不自动加入任何空间。

空间建立协作范围

经空间准入成为参与者，再按角色和任务取得授权。采购需求、合同、风险意见、单证和验收证据分别控制可见范围。

事项组织这一轮工作

一个具体目标形成一个事项，相关人和各自 Agent 在其中共同推进。谈判、CFO评议、履约可以关联或并行，争议形成有责任人的子事项。

工件与看板推动交接

工件承载证据、授权和版本；看板汇集共同事实、分歧、责任和确认状态。阶段条件满足后，生成带来源的交接包，并触发后续事项。

02 / 控制工件与看板

协作怎样变成可以继续执行的依据

对象它回答的问题采购中的例子
需求工件本轮需要解决什么品类、数量、到货窗口、质量标准
授权工件谁可以做什么，到哪里停止可核验与询样；价格承诺、签约和付款另行授权
版本与证据工件当前结论依据哪一版资料条款快照、合同版本、样品报告、单据差异及更正回单
共同决策看板各方对哪些事实达成确认，哪些还未解决条件共识、未决风险、补件责任、各方确认记录
交接工件下一事项可以接着做什么已确认版本、最小资料快照、参与角色、任务与限制

一段聊天或一句“同意”需要落实到明确对象、版本和授权范围，才能成为下一步的依据。看板确认、合同签署、付款执行与实际到账分别保留各自的记录。

03 / 循环与分支

既能向前推进，也能处理分歧后回到主线

阶段交接

撮合 → 谈判 → 履约

准备度确认后启动谈判；谈判中的财务风险可派生 CFO 评议；取得约定的签署回单后，才创建履约事项。

异常回路

履约 → 争议子事项 → 履约

例如提单与装箱单数量不一致，邀请货代、关务和相应责任方核对来源。更正和复核完成后，回到履约看板解除对应阻塞。

新一轮业务

验收 → 复盘 → 新采购需求

复盘沉淀本单证据与经验；再次采购需要新的需求和授权。可复用方案、经授权的经验与结构，重新开始下一轮协作。

04 / 实现这张图的关键约束

循环由明确条件驱动，各方保留决定权

  1. 邀请与数据授权分开。拉人或 Agent 进事项时，指定任务和可用材料；不能因为进入空间就读取全部资料。
  2. 看板触发绑定具体版本。规则检查必需的确认、授权有效性和外部回执；缺项时保留待办，不向下一阶段推进。
  3. 重复事件关联同一后续事项。每次交接保留唯一标识及来源，避免反复创建事项或重复执行外部动作。
  4. 分歧保留责任和依据。争议子事项明确问题、当事方、证据和解决条件；解决后由责任主体确认并回写父事项。
  5. 业务执行仍在授权方的系统发生。各方 Agent 通过获准接口连接本方或专业服务，带回可核验的结果；空间提供协作组织与交接关系。
